Performance pilot protocol

ItemDefinition
GenerationSame seed-42 checkpoint; archived prefixes near 0/32/64/96 tokens; one of four verbalization queries per prefix; 32 greedy tokens; no early EOS; one warmup per mode; three alternating timed repetitions; GPU synchronized.
CacheFresh model-native cache per call; prefill once; subsequent single-token embeddings; no cross-candidate cache sharing; original sampling rules preserved.
AgreementFixed-token replay compares cached and uncached next-token distributions on the same path. Acceptance: maximum KL ≤0.02 nats and top-1 agreement ≥90% per case; repeated cached calls must match. BF16 outputs need not be bitwise identical.
MemoryPeak PyTorch allocated/reserved memory after warmup, with allocator cache emptied before each timed sample; total and above-baseline peaks saved. Includes model, soft prompt, and retained diagnostic state; paired cache modes share each case baseline. Excludes driver/non-PyTorch allocations. Paired peak differences are the cache comparison.
ScoringSame 256 selection examples, same 101-token winning prompt; longest 32 examples also tested. Minibatches 1/2/4/8/16/32/64/128/256 up to example count, stop after OOM; one warmup plus three complete timed evaluations; absolute NLL difference <0.005.
Run settingScoring minibatch stays 1. Cache is the new utility default with explicit uncached reproduction option.
Extra-attempt attributionEach attempt records parent length, allocation source, whether parent is outside round-start global top four, prior expansion count, earlier-round revisits, duplicate/new outcome, and first-discovered candidate. Bucket improvement is against the round-start bucket best, including first entries into empty buckets. Returned-candidate lineage counts first-discovery edges; duplicate rediscoveries do not change attribution. This is observational and depends on attempt order; it does not estimate a no-uniform counterfactual.
